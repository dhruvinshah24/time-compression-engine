## A. Current TCE Bottlenecks

### BOTTLENECK A1 — Activity Recognition (CRITICAL GAP)
Stage: S05 (activity_classifier.py) / S07

Current method: Pure kinematic heuristics on 2D bounding-box centroid trajectories.

The decision tree in activity_classifier.py:
  cycling_conf >= 0.60  -> "cycling"
  stair_conf  >= 0.55   -> "walking_upstairs/downstairs"
  mean_speed >= RUN     -> "running"
  mean_speed >= WALK    -> "walking"
  very slow > 12s       -> "loitering"
  else                  -> "standing"

Cannot distinguish:
- Running vs. fast walking (same speed signal; different body posture)
- Crouching vs. sitting (requires hip/knee relation)
- Reaching up vs. arms raised (requires wrist position)
- Crawling (requires near-horizontal body)
- Falling (partially covered by pose_temporal.py only)
- Carrying an object
- Loitering vs. queueing

Evidence: Final assessment Category B — "Implemented and Exercised but Not Fully Accuracy-Validated."
No ground-truth confusion matrix exists for activity recognition.
Severity: HIGH.

### BOTTLENECK A2 — Pose Estimation Quality (MAJOR GAP)
Stage: S07 Pass 3 (pose_estimate.py) using yolov8n-pose (NANO model)

Problems:
- yolov8n-pose has significantly lower keypoint accuracy than yolov8m-pose.
- Nano model fails on rear-view, partial occlusions, extreme angles.
- Pose only covers 3 events (sitting/standing/reaching_up); keypoints contain richer info.
- Pose inference runs on every frame, including frames with no person.
- Pose track IDs NOT linked to MOT tracks from S05:
    Use track_id=-1 (scene-level) since pose doesn't track IDs
  This means pose events have no person identity.
Severity: MAJOR.

### BOTTLENECK A3 — Tracking: No Appearance Features (MAJOR GAP)
Stage: S05 (tracker.py)

Current method: Pure IoU Hungarian assignment (SORT-like).
Config: iou_threshold=0.25, max_lost_frames=15

Problems:
- When two people cross or a person is occluded, IoU-based tracking fails.
- max_lost_frames=15 still only covers short occlusions; appearance would cover longer ones.
- ReID runs AFTER tracking completes — cannot recover fragmented mid-sequence tracks.
- Phase 6E.14 produced 954 total tracks for 595s video (187 confirmed person tracks).
  Confirmation rate ~19.6%. High fragmentation is evident.
Severity: MAJOR.

### BOTTLENECK A4 — Detection: No Small-Object Strategy at Runtime (MODERATE GAP)
Stage: S04

SAHI is implemented (sahi_detector.py) but disabled by default:
    use_sahi = bool(context.settings.get("use_sahi", False))   # OFF
Problems:
- On modern 1080p CCTV footage, persons at 10-20m occupy ~20-40px.
- YOLO11L at 640px inference shrinks that to <5px - below detection threshold.
- No adaptive resolution strategy exists.
Severity: MODERATE for 320x240 footage; HIGH for modern 1080p.

### BOTTLENECK A5 — Story Construction: No Causal/Temporal Linking (MODERATE GAP)
Stage: S09

EventGraph has SAME_TRACK_TEMPORAL and CO_OCCURRENCE edges but no CAUSAL edges.
Multi-track interactions are not reconstructed as single narrative arcs.
"Person approaching vehicle then entering it" = 4 separate events, no parent arc.
Severity: MODERATE.

### BOTTLENECK A6 — Scene Understanding: No Generalized Context (MODERATE GAP)
Stage: S07

Scene understanding implemented ONLY for stairs (SceneStairGuard).
No scene context for: road, sidewalk, doorway, corridor, parking, indoor/outdoor.
Event rules do not adapt based on scene type.
Stair guard is feature-flagged OFF by default.
Severity: MODERATE.

### BOTTLENECK A7 — Compression Ranking: No Novelty/Redundancy Signal (MINOR)
Stage: S10

Two-factor weighted score only: importance*0.4 + narrative*0.6
No novelty penalty for repeated similar events.
No redundancy detection across different persons doing the same thing.
Severity: MINOR.

### BOTTLENECK A8 — Low-Light: Heuristic Preprocessing Only (MINOR)
Stage: S04 (low_light.py)

CLAHE was automatically BYPASSED on archive_001 (daylight footage).
Never tested on real dark CCTV in the validated pipeline.
Severity: MINOR for current footage; Moderate for night CCTV.

## FINAL DECISION

TOP PRIORITY #1 — Upgrade Pose Model and Link Pose to Tracks

Rationale:
- The yolov8n-pose (nano) runs on every frame but produces floating pose events
  with track_id=-1 — no person identity.
- Upgrading to yolov8m-pose: +15-25% keypoint accuracy, same API, same integration.
- Linking pose to MOT tracks via spatial bbox overlap is a contained algorithm change.
- Unlocks: crouching (knee-bend angle), falling (body collapse), crawling (horizontal body),
  reaching (wrist above shoulder with lean).
- No training required. Drop-in model swap.
- VRAM cost: +300 MB. Latency cost: +4 ms/frame. RTF: 0.199 -> ~0.22.

TOP PRIORITY #2 — Appearance-Augmented Tracker (ByteTrack + OSNet ReID)

Rationale:
- 954 total tracks for 595s video = severe fragmentation. Same person is split
  into multiple tracks every time they are briefly occluded.
- This corrupts downstream story construction and compression policy.
- ByteTrack with appearance embeddings re-identifies persons after occlusion.
- OSNet-x0_25 (~25 MB VRAM) provides purpose-built ReID embeddings vs. MobileNetV3
  which was designed for image classification, not ReID.
- Expected: 40-60% fewer track breaks, cleaner per-person narrative arcs.
- No training required. Both models are pretrained.
- VRAM cost: +130 MB. Latency cost: +5 ms/frame. RTF: 0.199 -> ~0.22.

TOP PRIORITY #3 — Lightweight Temporal Activity Classifier (X3D-XS or MoViNet-A2)

Rationale:
- Kinematic classifier cannot distinguish falling from fast crouch.
- Cannot see "picking up object" from velocity alone.
- X3D-XS (3.8 MB, 5ms/clip) covers Kinetics-400 activities including:
  walking, running, sitting down, standing up, climbing stairs, falling, crouching.
- MoViNet-A2 (20 MB, 15ms/clip) streams — no frame buffering needed.
- Use as ENSEMBLE: kinematic handles high-confidence cases; temporal model
  resolves ambiguous cases.
- No fine-tuning required for first iteration (Kinetics-400 covers TCE activities).
- VRAM cost: +30 MB. Latency cost: +3 ms/frame avg. RTF: 0.199 -> ~0.23.

COMBINED IMPACT OF ALL 3:
  Additional VRAM: ~460 MB -> total ~1,443 MB (within 8 GB budget)
  Estimated RTF: 0.199 -> ~0.27 (still 3.7x faster than real-time)
  No training required for initial deployment
  No production code modified during this investigation
